# 下一步 · 第三轮结束时的优先级

按「先可观测、再性能、最后需要授权」排序。每条给出验收标准与所需证据。

## P1（建议下一轮先做，均不需要授权）

### NS-1 · 让前端展示会话/渲染状态（承接 MJC-P3-107）

现状：`render_requested`、订阅计数只存在于 API 与日志，排障必须 curl。
验收：控制台 UI 能看出「有会话但无订阅者」「渲染中」「worker 已退出」三种状态；
浏览器断言覆盖这三种态；不新增轮询压力（复用既有 status 轮询）。
证据：浏览器 E2E 新增断言 + 截图。

### NS-2 · 消除"取消创建"产生的孤儿会话（MJC-P3-211）

现状：客户端中途取消 `POST /api/sessions` 时，服务端可能已经创建会话，
UI 拿不到 id，只能等空闲回收（`SESSION_IDLE_SECONDS=900`）。
候选方案（择一，需实测）：
1. 创建接口支持幂等键，客户端重试可复用同一会话；
2. 创建接口在返回后短窗内检测"从未被任何客户端订阅/查询"的会话并提前回收；
3. 缩短空闲回收时间（需要实测是否会误杀"长时间暂停观看"的正常会话）。
验收：注入"创建后立刻取消"的客户端，`GET /api/sessions` 在 N 秒内回到 0；
不误杀正常会话。证据：脚本 + `GET /api/sessions` 前后对照。

### NS-3 · 扩展 CI 门禁到"镜像内容清单"

现状：本轮只对 `schemas/` 做了镜像内容检查。
验收：CI 断言镜像内必须存在 `app/`、`envs/`、`schemas/`、`scripts/validate_manifests.py`，
且 `.dockerignore` 不排除这些路径（可用一条测试直接比对两处清单，防止再次漏拷）。
证据：CI 日志 + 单元测试。

### NS-4 · 收敛 uvicorn 默认线程池（MJC-P3-106）

现状：流端点用 `asyncio.to_thread` 轮询，uvicorn 线程池按需扩张（曾观察到约 16 线程）。
验收：改用专用单线程 executor 后，`/proc/<pid>/status` 的 Threads 有上界，
且 3 viewer 场景帧率不下降。证据：前后 Threads 数与 `sampler.py` 对照。

## P2（需要授权或外部条件）

### NS-5 · 小时级稳定性（需授权）

**NOT_RUN**：会占用同机资源，可能影响 27 个业务容器。
计划：≥2 小时，1 会话 + 1 训练 + 周期性连接/断开，记录 CPU/内存/线程数曲线与是否回落。
验收：无线性增长、断开后 CPU 回落至 <5%、无会话泄漏。

### NS-6 · 第三方局域网真机验收（缺设备）

**NOT_RUN**：本轮以 ffmpeg/OpenCV 作为第三方客户端替代，未用真实手机/笔记本浏览器。
验收：真机登录、观看、训练、回放，并记录连接中/断开后的容器 CPU。

### NS-7 · PPO 收敛性（需授权/算力）

验收：≥200k 步 PPO 与随机基线对比，回报曲线与 checkpoint 可回放。

### NS-8 · 增加真实接触型 gym 示例环境

验收：新增一个 `MultiInputPolicy`（obs dict）的本地示例，manifest 通过 schema，
`smoke_test.py --all` 通过，训练冒烟可跑。

## 维护提醒（易踩的坑）

1. **新增随镜像发布的目录**：先查 `.dockerignore`，再写 `COPY`；CI 的镜像内容检查会兜住，但别依赖它。
2. **新增程序化读帧消费者**：必须先 `subscribe()`（第二轮 MJC-P1-102 的教训）。
3. **改渲染/线程预算前**：先跑 `.artifacts/loop_probe.py` 重新测量。
4. **给结论标版本**：只能引用 `code_sha`/`validated_sha`；测试计数必须写档位。
5. **动 `.artifacts/` 下的脚本后**：注意 heredoc 与引号嵌套（本轮两次因 `"""` 与 `PY` 冲突导致补丁未生效，
   已改为结构化编辑）。
6. **跑 E2E 前**：先确认 `GET /api/sessions` 为空，否则 `MAX_VIEWERS=3` 会被上一次运行占满。
